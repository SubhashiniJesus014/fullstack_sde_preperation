what is a callback function?
A callback is a function that you pass to another function so that it can be called at the appropriate time.
Let's understand exactly what that means.

Imagine you order food at a restaurant.
1. You place your order.
2. The restaurant prepares your food.
3. When the food is ready, the restaurant calls you.
You don't need to stand in the kitchen and watch the food being prepared. You provide your contact details, and the restaurant contacts you when the task is ready.

A callback works in a similar way: you give a function to another function, which calls it when appropriate.
--->In JavaScript, callbacks are used for event handling, array operations, asynchronous operations, and reusable functions.

Your first callback function
Consider this simple code:
function greet() {
    console.log("Hello, Subhashini!");
}

function process(callback) {
    callback();
}

process(greet);

Output:
Hello, Subhashini!

Let's break it down line by line.
Step 1: Create a function

function greet() {
    console.log("Hello, Subhashini!");
}
This defines a function called greet. It does not execute yet.

Step 2: Accept a function as an argument
function process(callback) {
    callback();
}
Here, callback is a parameter that will receive a function.

Inside process, callback() executes the function it received.
Step 3: Pass greet to process
process(greet);

Execution flow
process(greet)
callback now refers to greet
callback() executes greet()
Hello, Subhashini!

Interview takeaway: greet and callback refer to the same function in this example. The name callback is simply the parameter name.

The most important difference: greet vs greet()
This is one of the most common beginner mistakes and a frequent interview concept.

function greet() {
    console.log("Hello!");
}
There are two different things you can do.
A. Pass greet
process(greet);
You pass the function itself. The receiving function can decide when to execute it.
B. Pass greet()
process(greet());
You execute greet immediately and pass its return value to process.

For example:
function greet() {
    console.log("Hello!");
    return 100;
}

function process(callback) {
    console.log("Inside process:", callback);
}

process(greet);

Output:
Inside process: [Function: greet]

The function was passed but not executed.

Now change the last line:
process(greet());

Output:
Hello!
Inside process: 100

Why?
1. greet() runs immediately and prints "Hello!".
2. It returns 100.
3. process() receives 100, not the function.
4. The receiving function does not have a callback to execute.
Remember: Use greet when passing a function as a callback. Use greet() when you want to execute it immediately.

Passing data to a callback
In real applications, callbacks often need data.

Consider this example:
function calculate(a, b, callback) {
    const result = a + b;
    callback(result);
}

function display(value) {
    console.log("Result:", value);
}
calculate(10, 20, display);

Output:
Result: 30

Let's understand the flow:
- calculate() receives 10, 20, and the display function.
- It adds the numbers to get 30.
- It calls callback(result).
- That becomes display(30).
- display() prints the result.
Notice that the callback can receive arguments just like any normal function.

Try changing the callback
function calculate(a, b, callback) {
    callback(a, b);
}

function multiply(x, y) {
    console.log(x * y);
}

calculate(10, 20, multiply);

Output:
200

We reused calculate() without changing its implementation. By passing a different callback, we changed what it does.
This is a key benefit of callbacks: they allow you to customize behavior without rewriting the main function.

Real-world example: An e-commerce payment system
Imagine you are building a shopping website.

After the payment succeeds, you want to display a success message. If it fails, you want to display an error.
You could design a function that accepts a callback for each outcome:

function processPayment(amount, onSuccess, onFailure) {
    if (amount > 0) {
        onSuccess(amount);
    } else {
        onFailure("Invalid payment amount");
    }
}

function showSuccess(amount) {
    console.log("Payment successful:", amount);
}

function showError(message) {
    console.log("Payment failed:", message);
}

processPayment(1500, showSuccess, showError);
processPayment(0, showSuccess, showError);

Output:
Payment successful: 1500
Payment failed: Invalid payment amount

Callbacks in asynchronous JavaScript
This is particularly important for product-based company interviews.

JavaScript often needs to perform operations that take time, such as waiting for a timer, responding to a click, or receiving data from a server.

Consider setTimeout():
console.log("Start");

setTimeout(function() {
    console.log("Task completed");
}, 2000);

console.log("End");
Output:
Start
End
Task completed

Why doesn't "Task completed" print immediately?
1. JavaScript prints "Start".
2. It registers the timer through setTimeout().
3. JavaScript continues and prints "End".
4. After the delay, the timer callback becomes eligible to run and is executed when the event loop can process it.
The callback is the function passed to setTimeout():

function() {
    console.log("Task completed");
}
Another example: Arrow function callback
The callback can also be written as an arrow function:

setTimeout(() => {
    console.log("Order ready!");
}, 1000);
Both normal functions and arrow functions can be callbacks. Choose between them based on their behavior, especially how they handle this.

Real-world example: Button click in a website
Suppose you have a login button:
<button id="loginBtn">Login</button>
JavaScript:
const button = document.getElementById("loginBtn");

button.addEventListener("click", function() {
    console.log("Login button clicked!");
});
Here, the anonymous function is a callback.

The browser registers it and calls it when the user clicks the button.

You don't call the function manually. The browser calls it in response to the event.

The same idea applies to:
- Dropdown menus.
- Form validation.
- React event handlers.
- Modal windows.
- Search buttons.
This is a key distinction: the code that receives a callback does not always call it immediately. It may call it later when a particular event occurs.

Callbacks in array methods: map(), filter(), and reduce()
You have already started learning higher-order functions. Now connect the two concepts.

A callback is the function you provide. A higher-order function is the function that accepts or returns another function.

For example:
const numbers = [10, 20, 30];

const result = numbers.map(function(num) {
    return num * 2;
});

console.log(result);

Output:
[20, 40, 60]

Here:
- map() is the higher-order function.
- function(num) { return num * 2; } is the callback.
- map() calls the callback for each array element.
- The returned values form a new array.
The same example using an arrow function:

const result = numbers.map(num => num * 2);
Know these callback patterns for interviews
Method	            What the callback does	                           Example
map()	              Transforms each element                 	          nums.map(n => n * 2)
filter()	          Decides which elements to keep	                    nums.filter(n => n > 10)
find()	            Tests elements until the first match	              nums.find(n => n > 10)
some()	            Tests whether at least one element matches	        nums.some(n => n > 10)
every()	            Tests whether all elements match	                  nums.every(n => n > 0)
reduce()	          Combines values into an accumulated result	        nums.reduce((sum, n) => sum + n, 0)

Synchronous vs asynchronous callbacks
---synchronous callback---
This is an important distinction for JavaScript interviews.
function process(callback) {
    console.log("A");
    callback();
    console.log("C");
}

process(() => console.log("B"));

Output:
A
B
C
The callback executes immediately during the process() call.

Asynchronous callback
console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
Output:
A
C
B
The timer callback runs later through the event loop, even with a delay of zero.

A callback is not automatically asynchronous. It can be synchronous or asynchronous depending on how it is used.

What is callback hell?
Suppose an application needs to:
1. Log in a user.
2. Fetch the user's profile.
3. Fetch the user's orders.
4. Process the order details.
If each operation uses a nested callback, the code can become difficult to read:

loginUser(function(user) {
    getProfile(user, function(profile) {
        getOrders(profile, function(orders) {
            processOrders(orders, function(result) {
                console.log(result);
            });
        });
    });
});

This deeply nested structure is often called callback hell.
It can make error handling, debugging, and maintaining the code difficult.
Modern JavaScript often uses Promises and async/await to make asynchronous flows easier to read:
async function loadUserData() {
    const user = await loginUser();
    const profile = await getProfile(user);
    const orders = await getOrders(profile);
    return processOrders(orders);
}
This is illustrative code: the functions must return Promises for this await pattern to work as intended.
Remember, callbacks are still widely used. Promises and async/await help structure asynchronous operations; they do not eliminate callbacks from JavaScript.

Five things to remember forever
1. Callback: A function passed to another function so it can be called.
2. Passing a function: process(greet) passes the function; process(greet()) executes it first.
3. Higher-order function: A function that accepts another function or returns a function.
4. Asynchronous callback: A function called later, for example after a timer or user event.
5. Callback hell: Deeply nested callbacks that make asynchronous code difficult to manage.
