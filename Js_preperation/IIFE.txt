--->what is IIFE?
IIFE stands for Immediately Invoked Function Expression.
An IIFE is a function that is defined and executed immediately, without needing to call it separately later.
It is a JavaScript concept worth understanding for interviews because it helps explain function expressions, scope, closures, and data privacy.

1. WHAT IS AN IIFE?
-------------------
IIFE = Immediately Invoked Function Expression.

An IIFE is a function expression that is executed immediately after it is defined.

Example:
(function () {
    console.log("Hello");
})();

Output:
Hello

The first parentheses make the function an expression. The final () invokes it.

Arrow-function IIFE:
(() => {
    console.log("Executed immediately");
})();

2. NORMAL FUNCTION VS IIFE
--------------------------
Normal function:
function greet() {
    console.log("Hello");
}
greet(); // called separately

IIFE:
(function greet() {
    console.log("Hello");
})(); // executes immediately

3. COMMON IIFE FORMS
--------------------
Anonymous IIFE:
(function () {
    console.log("Anonymous");
})();

Named IIFE:
(function greet() {
    console.log("Named");
})();

Arrow IIFE:
(() => {
    console.log("Arrow IIFE");
})();

IIFE with parameters:
(function (a, b) {
    console.log(a + b);
})(10, 20);
// Output: 30

IIFE returning a value:
const result = (function () {
    return 50 + 25;
})();
console.log(result); // 75

4. WHY USE AN IIFE?
-------------------
Historically, IIFEs were used to:
- Create a private function scope.
- Keep temporary variables out of the surrounding/global scope.
- Avoid naming conflicts.
- Initialize code immediately.
- Create private state with closures.

Modern JavaScript also offers let, const, block scope, and ES modules, so IIFEs are not required for every use case.

5. SCOPE: LOCAL VS OUTER VARIABLE
---------------------------------
var x = 10;

(function () {
    var x = 30;
    console.log(x);
})();

console.log(x);

Output:
30
10

The inner x is local to the IIFE. It does not replace the outer x.

6. IIFE, CLOSURES, AND PRIVATE COUNTER
--------------------------------------
const counter = (function () {
    let count = 0;

    return {
        increment: function () {
            count++;
            return count;
        },
        decrement: function () {
            count--;
            return count;
        },
        getCount: function () {
            return count;
        }
    };
})();

console.log(counter.increment()); // 1
console.log(counter.increment()); // 2
console.log(counter.decrement()); // 1
console.log(counter.getCount());  // 1

How it works:
- The IIFE executes once and returns an object.
- count is private: outside code cannot access it directly.
- Returned methods retain access to count through closures.
- return sends a value to the caller; console.log only prints a value.
- Without an explicit return, a JavaScript function returns undefined.

7. IIFE + var + setTimeout (CLASSIC INTERVIEW QUESTION)
-------------------------------------------------------
for (var i = 1; i <= 3; i++) {
    setTimeout(function () {
        console.log(i);
    }, 100);
}

Output:
4
4
4

Why:
- var is function-scoped, not block-scoped.
- All three callbacks refer to the same i.
- The loop finishes first; i becomes 4.
- Then callbacks run and read that shared variable.

Fix with IIFE:
for (var i = 1; i <= 3; i++) {
    (function (num) {
        setTimeout(function () {
            console.log(num);
        }, 100);
    })(i);
}

Output:
1
2
3

Why:
- Each IIFE invocation receives the current i as num.
- Each invocation has its own parameter binding.
- The callback closes over that invocation's num.

8. let + setTimeout
-------------------
for (let i = 1; i <= 3; i++) {
    setTimeout(function () {
        console.log(i);
    }, 100);
}

Output:
1
2
3

In this kind of for loop, let creates a separate iteration binding for i. Each callback closes over the appropriate binding. An IIFE is unnecessary.

Comparison:
- var without IIFE: 4, 4, 4
- var with IIFE:    1, 2, 3
- let without IIFE: 1, 2, 3
- let with IIFE:    1, 2, 3 (works, but usually redundant)

Important: setTimeout does not save the value by itself. The closure and the variable bindings determine what the callback reads.

9. IMPORTANT DIFFERENCE: console.log VS return
-----------------------------------------------
function increment() {
    let count = 0;
    count++;
    console.log(count);
}

console.log(increment());

Output:
1
undefined

The function prints 1 internally, but has no return statement. Therefore, the outer console.log prints undefined.

Correct if the caller needs the value:
function increment() {
    let count = 0;
    count++;
    return count;
}
console.log(increment()); // 1

10. INTERVIEW QUESTIONS (CONCEPTUAL)
------------------------------------
Q1. What does IIFE stand for?
Answer: Immediately Invoked Function Expression; it executes immediately after being defined.

Q2. Why are parentheses used around an IIFE?
Answer: They make the function a function expression so it can be invoked immediately.

Q3. What are common uses of IIFE?
Answer: Isolated function scope, avoiding naming conflicts, immediate initialization, and private state with closures.

Q4. Can an IIFE accept parameters and return a value?
Answer: Yes, like any other function.

Q5. What is a closure?
Answer: A function together with access to variables from its surrounding lexical scope, even after the outer function has finished.

Q6. How does an IIFE help create private data?
Answer: Variables declared inside it are not directly accessible outside, but returned methods can access them through closures.

Q7. Does the IIFE in the counter example run every time counter.increment() is called?
Answer: No. The IIFE runs once when the expression is evaluated. The returned method is called repeatedly.

Q8. Why does var print 4, 4, 4 in a setTimeout loop?
Answer: All callbacks share the same var binding, and the loop finishes with i equal to 4 before callbacks execute.

Q9. How does IIFE fix the var loop?
Answer: It receives the current i as a parameter, creating a separate parameter binding for each invocation.

Q10. Why does let print 1, 2, 3 without an IIFE?
Answer: A for loop using let creates a separate binding for each iteration.

Q11. Is IIFE still necessary in modern JavaScript?
Answer: Not always. let, const, and ES modules cover many use cases, but IIFEs remain useful for immediate execution and isolated state.

Q12. What is the difference between console.log and return?
Answer: console.log displays a value; return passes a value back to the caller and ends that function invocation.

Q13. What is a named IIFE?
Answer: An IIFE with a name, such as (function greet() {})(). Its name is generally available only inside that function expression, not as an outer variable.

Q14. Can arrow functions be used as IIFEs?
Answer: Yes: (() => { console.log("Hi"); })();

Q15. Does var create a new variable for each loop iteration?
Answer: No. In a typical for loop, var uses one shared binding. let creates per-iteration bindings in this loop form.

15. QUICK REVISION
------------------
- IIFE = Immediately Invoked Function Expression.
- Standard syntax: (function () { ... })();
- Arrow syntax: (() => { ... })();
- IIFE executes immediately; a returned function can be called later.
- IIFE creates function scope.
- Closure lets an inner function retain access to outer lexical variables.
- var is function-scoped; in the classic loop, callbacks share one i.
- let is block-scoped and creates per-iteration bindings in a for loop.
- console.log prints; return sends a value back to the caller.
- IIFE + var can preserve loop values by passing the current value as a parameter.
- For modern code, let often removes the need for the loop IIFE.

Interview strategy:
For every output question, explain:
1. Which scope each variable belongs to.
2. Whether the callback executes now or later.
3. Which binding the callback closes over.
4. Whether the function returns a value or only prints one.
