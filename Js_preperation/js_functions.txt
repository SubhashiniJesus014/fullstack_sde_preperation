1. Function declaration

A function declaration defines a function using the function keyword and a function name.

function add(a, b) {
    return a + b;
}

console.log(add(10, 20)); // 30

Here:
- function is the keyword.
- add is the function name.
- a and b are parameters.
- return a + b returns the result.

***Important interview concept: Hoisting
You can call a function declaration before its definition.

2. Function expression
A function expression creates a function and assigns it to a variable.

const add = function(a, b) {
    return a + b;
};

console.log(add(10, 20)); // 30


Notice that the function itself has no name. This is called an anonymous function expression.
A named function expression is also possible:

const add = function calculate(a, b) {
    return a + b;
};

console.log(add(2, 3)); // 5

***Important interview concept: Hoisting
You cannot call a function expression before its variable has been initialized.

console.log(add(5, 3)); // ReferenceError

const add = function(a, b) {
    return a + b;
};

Why? The variable add is in the temporal dead zone until its declaration is initialized.
With var, the behavior differs:

console.log(add); // undefined
add(2, 3);        // TypeError

var add = function(a, b) {
    return a + b;
};

var is hoisted and initialized to undefined, 
but the assigned function is not available until the assignment executes.

3. Arrow function
Arrow functions provide a shorter syntax for writing function expressions.

const add = (a, b) => {
    return a + b;
};

console.log(add(10, 20)); // 30

***For a single expression, you can use an implicit return:

const add = (a, b) => a + b;

console.log(add(10, 20)); // 30


****Important interview concept: Arrow functions behave differently****
Arrow functions:
- Do not have their own this; they inherit it from the surrounding scope.
- Do not have their own arguments object.
- Cannot be used as constructors with new.
- Are not hoisted as callable function declarations. A const or let variable holding an arrow function cannot be accessed before initialization.

Example of lexical this:

const user = {
    name: "Ravi",

    greet: function() {
        console.log(this.name);
    },

    greetArrow: () => {
        console.log(this.name);
    }
};

user.greet();      // "Ravi"
user.greetArrow(); // Usually undefined in a normal script

The regular method gets this from the object used to call it. The arrow function inherits this from the surrounding scope instead.

****In React, arrow functions are commonly used for callbacks and event handlers.

const handleClick = () => {
    console.log("Button clicked");
};


-------------Questions -------------

1. What is the difference between a function declaration and a function expression?
A function declaration defines a function directly using the function keyword, 
whereas a function expression creates a function and assigns it to a variable.

2. What is hoisting in JavaScript?
Hoisting is JavaScript's behavior of processing declarations before executing the code in their scope.
Consider this example:

console.log(a); // undefined
var a = 10;

Why does it print undefined?
Conceptually, JavaScript processes it like this:
var a;
console.log(a); // undefined
a = 10;

Now consider a function declaration:
greet(); // Hello

function greet() {
    console.log("Hello");
}
This works because the function declaration is available before its position in the source code is reached.
But with let and const:
console.log(a); // ReferenceError
const a = 10;

The variable cannot be accessed before initialization.
Interview answer: Hoisting is JavaScript's handling of declarations before code execution. 
Function declarations are available before their definition, var is initialized to undefined, 
and let and const remain inaccessible until initialization.

3. What is the Temporal Dead Zone (TDZ)?
The Temporal Dead Zone is the period between entering a scope and initializing a let or const variable. Accessing that variable during this period causes a ReferenceError.
Example:
{
    // TDZ starts for a here

    console.log(a); // ReferenceError

    let a = 10; // TDZ ends for a
}

Another example:
console.log(name); // ReferenceError

const name = "Ravi";

Why does this happen?
JavaScript knows about the name binding, but it does not allow access to it before initialization.
Interview answer: The TDZ is the time during which a let or const variable exists in its scope but 
cannot be accessed because it has not yet been initialized.

4. Why do arrow functions not have their own this?
Arrow functions use lexical this, which means they inherit this from their surrounding scope instead of creating their own this.
Example:
const user = {
    name: "Ravi",

    greet: function() {
        const arrow = () => {
            console.log(this.name);
        };

        arrow();
    }
};

user.greet(); // Ravi

Here is why:
1. user.greet() calls the regular function as an object method.
2. Therefore, this inside greet refers to user.
3. The arrow function inherits that same this.
4. So this.name prints "Ravi".
Interview answer: Arrow functions do not have their own this. They inherit it lexically from the surrounding scope, 
which makes them useful for callbacks that need to preserve the surrounding this value.

5. What is the difference between this in a regular function and an arrow function?
The main difference is how this is determined.
- Regular function: Its this generally depends on how the function is called.
- Arrow function: Its this is inherited from the surrounding lexical scope.
Example:
const user = {
    name: "Ravi",

    regular: function() {
        console.log(this.name);
    },

    arrow: () => {
        console.log(this.name);
    }
};

user.regular(); // Ravi
user.arrow();   // Usually undefined in a normal script

The regular function receives this from the method call user.regular().
The arrow function does not receive this from user.arrow(). It inherits this from the scope where the arrow function was created.
Note: The arrow function's output can differ depending on whether the surrounding scope is a browser script, an ES module, or another environment.
Interview answer: Regular functions determine this from their call site, while arrow functions use lexical this from their surrounding scope.

6. Can we use an arrow function as a constructor? Why?
No. Arrow functions cannot be used as constructors.
Example:
const Person = (name) => {
    this.name = name;
};

const p = new Person("Ravi"); // TypeError

Why?
Arrow functions do not have their own this binding and do not have the internal constructor capability required by new.
Use a regular function instead:

function Person(name) {
    this.name = name;
}

const p = new Person("Ravi");

console.log(p.name); // Ravi

A class is another common option:

class Person {
    constructor(name) {
        this.name = name;
    }
}

const p = new Person("Ravi");
Interview answer: Arrow functions cannot be constructors because they lack the internal [[Construct]] capability required by the new operator. 
Use a regular constructible function or a class instead.

7. What is the difference between return a + b and () => a + b?
These are two different things.

First: return a + b
return is a statement that returns a value from the current function.

function add(a, b) {
    return a + b;
}

console.log(add(2, 3)); // 5

Second: () => a + b
This is an arrow function with an implicit return.
const add = (a, b) => a + b;
console.log(add(2, 3)); // 5

These two arrow function implementations are equivalent:
const add1 = (a, b) => a + b;

const add2 = (a, b) => {
    return a + b;
};

8. Can a function expression be named?
Yes. A function expression can be either anonymous or named.
Anonymous function expression:

const add = function(a, b) {
    return a + b;
};

Named function expression:
const add = function calculate(a, b) {
    return a + b;
};

console.log(add(2, 3)); // 5

In a named function expression, calculate is the internal function name. 
It can be useful for debugging and recursion.
For example:
const factorial = function fact(n) {
    if (n <= 1) {
        return 1;
    }

    return n * fact(n - 1);
};

console.log(factorial(5)); // 120

Here, fact can refer to the function inside its own body.
Interview answer: Yes, a function expression can be named or anonymous.
A named function expression is useful for debugging and recursive function calls.

9. What happens if we use var instead of const for a function expression?
Consider this example with const:

console.log(add); // ReferenceError
const add = function(a, b) {
    return a + b;
};

Now consider var:
console.log(add); // undefined

var add = function(a, b) {
    return a + b;
};

Why is the output different?
With var, the variable declaration is hoisted and initialized to undefined. The function is assigned only
when execution reaches the assignment.With const, the variable is in the TDZ until initialization, 
so accessing it early causes a ReferenceError.
One more important point:

console.log(add(2, 3)); // TypeError

var add = function(a, b) {
    return a + b;
};

This produces a TypeError because add is undefined when the call occurs, and undefined is not callable.
Interview answer: With var, the variable is hoisted and initialized to undefined, while with const, it remains in the TDZ until initialization.
In neither case is the assigned function available before the assignment executes.

10. Why are arrow functions commonly used in React event handlers?
Arrow functions provide concise syntax and preserve the surrounding this value when one is needed.

Example:
Here, handleClick is an arrow function passed to React as the event handler.
Benefits include:

function Counter() {
    const handleClick = () => {
        console.log("Button clicked");
    };

    return (
        <button onClick={handleClick}>
            Click me
        </button>
    );
}

1. Concise syntax: They make callback functions easier to write.
2. Lexical this: They preserve the surrounding this when used in contexts where this matters.
3. Callbacks: They work naturally with methods such as map, filter, and forEach.
